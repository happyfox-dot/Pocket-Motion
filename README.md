# Pocket 4P Port

基于 [MicageEritc/Pocket-Motion](https://github.com/MicageEritc/Pocket-Motion) 的本地改造版。
本分支的开发与合并在 [happyfox-dot/Pocket-Motion](https://github.com/happyfox-dot/Pocket-Motion) 进行。
目标是从 USB 连接的 Pocket 4P 读取原始实况素材，批量生成百度网盘可识别的实况封装，供 iPhone、小米、vivo、OPPO 手机下载保存。

**当前是待真机验证的版本。生成文件、结构检查通过，不等于百度网盘和全部手机已验证兼容。**

## Windows 使用

1. 双击根目录 `Start-Pocket4P.cmd`，或运行 `dist/Pocket4PPort/PocketMotion.exe`。保留应用旁的所有文件和 `data` 文件夹。
2. 用支持数据传输的 USB 线连接相机，在相机上选择文件传输／U盘模式。Windows 应能看到相机盘符；本程序暂不支持仅以 MTP 设备显示、没有盘符的连接。
3. 点击“查找 USB 相机 / 存储卡”。有多个候选时手动选择。也可以通过“更改”选择盘符根目录、`DCIM`、`DJI_001` 或已复制的素材文件夹。
4. 点击素材行或右侧的预览按钮，可在程序内查看照片、播放实况和视频。通过最右侧勾选框选择要导出的素材，按住 Shift 可连选。
5. 选择电脑上的导出位置，在“实况”分类中勾选素材，点击“导出百度网盘实况 (.livp)”。第一轮只选 1–3 张。
6. 打开导出文件夹，将 `baidu_live` 内的 `.livp` 原文件上传到百度网盘。上传由用户通过网盘客户端完成，本程序不登录网盘、不自动上传。
7. 在手机百度网盘 App 内尝试保存到系统相册。如出现格式选项，选择实况／本机适配格式，并检查系统相册中的动态、声音、封面和拍摄时间。

同名输出已经存在时会跳过，不覆盖。导出工作在独立临时目录中完成，失败不会留下正式输出文件。源素材只读，导出位置不能选在素材目录内部。已有文件的跳过依据是文件名，不代表校验过其内容；如需重新生成，请选择新的导出目录。

## 程序内预览

照片可放大查看，使用滚轮缩放、拖动画面。实况和普通视频支持播放／暂停、拖动进度、静音和循环播放；打开时保持暂停，实况默认启用循环。关闭预览会停止播放并释放文件。

这里预览的是已拍摄的原始素材，不是相机实时取景，也不是加水印后的导出效果。水印在导出时添加。暂不支持 DNG 原始照片预览，可查看配套 JPEG；文件丢失或设备断开时会提示重新连接和扫描。

Windows 程序附带视频播放组件，可解码 H.264／H.265 素材。请保留程序旁的 DLL 和 `data` 文件夹；相机实际分辨率、HDR 色彩及 USB 播放流畅度仍需接入真机后验证。

本机已使用合成 JPEG、H.265/AAC 实况片段和普通短视频完成窗口内验证：播放、暂停、循环、进度拖动、静音开关、照片缩放、损坏文件提示及关闭后返回列表。预览前后源文件校验一致，关闭后文件可被独占读取。自动测试另覆盖源文件丢失、DNG 提示和加载过程中关闭窗口；这些检查不替代相机实测。

## 添加机型文字水印

在“实况”分类的左侧打开 **添加机型水印**，即可添加 `DJI · Osmo Pocket 4P` 文字。默认右下角，也可选择左下、右上、左上角；设置会自动记住。首次使用默认关闭。

水印会同时出现在静态封面和完整动态视频中，适用于百度网盘、Apple 和 Android 三种实况导出。它是机型文字，不是 DJI Mimo 的官方图形 Logo 或画框。普通视频、照片分类仍按原文件复制。

带水印视频需要重新编码，耗时更长，不能算无损导出；音频仍直接复制。水印相对画面短边缩放，采用白字、暗色描边。导出名称会添加 `_WM_BR`（右下）、`_WM_BL`（左下）、`_WM_TR`（右上）或 `_WM_TL`（左上），与无水印结果区分；同一位置的已有结果仍会跳过。源文件不修改。

水印字体使用电脑已安装的 Arial 或 Segoe UI。当前已验证 Windows；如找不到字体，会提示失败，不会悄悄导出缺少水印的文件。

## 输出格式

| 按钮 | 输出 | 用途与边界 |
| --- | --- | --- |
| 百度网盘实况 | `baidu_live/*.livp` | HEIC 封面、配对 MOV 和网盘索引封装；网盘及手机兼容性待实测 |
| Apple 实况 | `live/*.HEIC` + `live/*.MOV` | 配对资源；不能把分开下载两个文件等同于已导入手机相册 |
| Android 动态照片（试验） | `live/*_MP.jpg` | Motion Photo 1.0 封装；尚未做小米、vivo、OPPO 专属格式适配 |
| 视频 / 照片 | `movie/` / `photo/` | 复制原文件 |

## 已完成的本地改造

- 查找挂载盘下的 `DCIM/DJI_*`，支持多个素材子目录。
- 沿用上游 `TPLG_VIDEO_LIVEPHOTO` 标记识别，不用时长把普通短视频误判成实况。
- 新增流式 LIVP 打包：未压缩 ZIP、CRC32、双资源索引注释。封装依据来自 [2livp 的格式研究](https://github.com/LetMeFly666/2livp)，本项目独立实现；这不是苹果或百度公开的稳定标准。
- 对短素材使用视频中点作为封面，正常素材沿用上游 1.5 秒选择。封面和配对时间标记一致。
- 编码器失败立即报告；先在临时目录生成，完成后才发布；已有结果跳过。
- 缺失设备信息时不再把任意素材标成 Pocket 4P。
- Windows 构建脚本同时准备 FFmpeg 和 ffprobe，并支持通过项目内目录联接处理插件目录，无需更改系统开发者模式。

## 必须知道的限制

- 尚无本机相机样本。实况识别是基于上游实机观察的启发式，只检查 MP4 前 512 KiB；无法识别的素材留在“视频”分类，不会自动转实况。
- HEIC 封面从视频抽帧生成，并会重新编码；不能宣称整个过程“全无损”。关闭水印时动态视频和音频直接复制编码流；开启水印后视频重新编码，音频仍直接复制。
- 封面时刻目前是处理策略，不代表已经解析出 DJI 的原始快门时刻。原件是否另含高质量静态图，仍待实测分析。
- 优先采用 DJI 文件名中的本地拍摄时间，其次采用可解析的容器时间；相机时钟、电脑时区及跨时区拍摄需单独核对。尚未完整保留 GPS、所有私有元数据或 HDR 信息。
- 上游媒体封装引擎会在内存中处理短视频。第一版用于实况短片，不用于将大型长视频转换为实况；LIVP 打包限制为小于 4 GiB。
- 同一份 `.livp` 能否经百度网盘转换为全部目标品牌的实况，尚未确认。不要把该按钮理解为已通过全品牌验证。
- 相册可播放不代表微信、小红书等第三方应用一定识别为实况；动态壁纸不在本次验收范围内。

## 连接真机后的验收

按以下流程记录机型、相机固件、手机系统版本、相册版本和百度网盘 App 版本：

1. 拍摄横向、竖向、有声音实况各一组，再拍一段普通短视频。
2. 检查扫描分类与相机回放一致，核对原件标记、时长、方向和拍摄时间。
3. 分别用 Mimo 和本工具导出同一组，比较封面、画质、声音、时长和时间信息。
4. 电脑上传生成的 `.livp`，分别用 iPhone、小米、vivo、OPPO 的百度网盘 App 保存到系统相册。
5. 检查是否为单张实况、能否播放、声音和方向是否正确、拍摄时间是否保留。把失败组合记下来再调整对应输出。

## 开发与构建

需要 Flutter（Dart >= 3.13）、Windows C++ 编译工具、FFmpeg（包含 libx265）和 ffprobe。本机的便携 Flutter 放在 `.tools/flutter`，不会加入 Git。

```powershell
# 检查、构建，并将程序与媒体工具复制到 dist/Pocket4PPort
powershell -File tools/build_windows.ps1

# 单独检查
.\.tools\flutter\bin\flutter.bat analyze --no-pub
.\.tools\flutter\bin\flutter.bat test --no-pub

# 生成明确标注为 synthetic 的测试素材，验证编码/打包流程
# 每次使用新的临时目录，避免跳过已有结果
.\.tools\flutter\bin\dart.bat run tools/media_smoke.dart .tools/media-smoke-new

# 水印：生成横竖屏、四角、短片、有声/无声样本，然后独立解码检查
.\.tools\flutter\bin\dart.bat run tools/watermark_smoke.dart .tools/watermark-smoke-new
python tools/verify_watermark.py .tools/watermark-smoke-new
```

测试包括目录扫描与分类、日期校验、输出保护、LIVP 索引和 CRC、无素材界面，以及真实编码器处理正常／短素材和损坏输入。它们不代替真实相机、百度网盘和手机相册的端到端验证。

水印验证还会检查封面与视频首帧／中段／末帧的文字位置、配对标识、音频编码内容保持、源文件不变，以及带水印和无水印文件可以共存。`verify_watermark.py` 只使用 Python 标准库和 FFmpeg / ffprobe，并会留下 `watermark-preview.png` 模拟画面预览。

上游的原始说明可通过 Git 历史查看。本地远程 `origin` 指向个人改造仓库，`upstream` 保留原项目地址，便于后续同步。
